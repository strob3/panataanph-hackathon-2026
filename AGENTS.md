# PanataanPH - Agent Instructions & Context

PanataanPH is a verified directory of Philippine relief drives and fundraisers. It combines local AI document extraction with human-led verification to evaluate fundraising legitimacy transparently during disasters.

---

## 2. Tech Stack

- **Frontend:** Next.js, React, TypeScript, Tailwind CSS
- **Backend:** Python 3.10+, FastAPI, Pydantic, SQLAlchemy / SQLModel
- **Database:** SQLite (`data/panataan.db`)
- **Document Processing:** PDF selectable text parser + PaddleOCR (scans/images)
- **Local LLM Runtime:** Ollama running `qwen3:4b`
- **Indexing & Tooling:** Tokless, CodeGraph (`codegraph_explore`), RTK

## 3. Core Principles & AI Guardrails

1. **Local-Only & Offline First:**
   - All AI inference and OCR must run locally on host.
   - **Never** forward uploaded documents, text, or metadata to external AI APIs (OpenAI, Gemini, Anthropic, etc.).
   - Core extraction and review workflow must run completely offline after setup.
2. **Extraction Only, Never Invent:**
   - LLM extracts structured fields from OCR/text.
   - LLM must return `null` for missing or unreadable fields; never hallucinate or assume.
   - LLM does **not** decide campaign legitimacy or predict fraud.
3. **Deterministic Scoring:**
   - Verification / Evidence Completeness Score (0-100) is computed strictly by deterministic Python application logic (`services/scoring.py`), not by LLM prompts.
   - Missing evidence does not equal fraud; it triggers human review.
4. **Human-in-the-Loop:**
   - Final approval/rejection is strictly decided by human administrators.
   - Statuses: `pending` → `under_review` → `needs_information` | `verified` | `rejected`.
5. **Privacy & Security Boundaries:**
   - Uploaded documents (permits, IDs, receipts) are confidential. Store in private filesystem (`storage/`), never in public static assets.
   - Public directory only shows verified campaigns and public metadata; never raw sensitive documents.
   - Sanitize filenames, enforce upload size/type limits (PDF, JPG, PNG).

## 4. Key Workflows & Commands

### Development Setup
```bash
# Backend setup
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload --port 8000

# Frontend setup
cd frontend
npm install
npm run dev

# Ollama Model
ollama pull qwen3:4b
```

### Testing & Verification
```bash
# Backend tests
pytest tests/ -v

# Frontend tests / linting
cd frontend && npm test && npm run lint
```

### Git Workflow (per WORKFLOW.md)
- Branch from latest `main`:
  - `feat/<feature-name>`
  - `fix/<bug-name>`
  - `docs/<topic-name>`
  - `refactor/<topic-name>`
- Create PR to merge into `main` after review.

## 5. Agent Guidelines & Tool Disciplines

- **Start of Session:**
  - Check repository state with `git status -s` and `git log -n 3 --oneline`.
  - Do not read every file on session start. Inspect only task-relevant files.
- **Codebase Navigation:**
  - Check `.codegraph/` first. Use `codegraph_explore` for symbol definitions, call graphs, and blast radius before grep or full reads.
  - Re-run `tokless index` after creating new modules or significant architectural changes.
- **Surgical Edits:**
  - Touch only code necessary for requested task.
  - Reuse existing models, schemas, and helpers before creating new ones.
  - Maintain type annotations (Python type hints, TypeScript interfaces).
